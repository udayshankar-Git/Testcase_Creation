## Background

For Excess accounts, the Underlying Insurance limit fields currently use numeric inputs and default to the policy currency. Users need to enter the currency together with each limit, including a currency different from the policy currency. The **Limit of Liability** field in the **Other Limit** section must support the same entry.

The change applies to these fields on the Excess Coverages screen:

- Occurrence Limit
- Other Aggregate Limit
- Products-Completed Operations Aggregate Limit
- Limit of Liability for each Other Limit entry

## User Story

**As an** EzDocs user preparing an Excess submission,  
**I want** to enter a currency and limit amount in the Underlying Insurance fields,  
**so that** the account’s underlying limits can be accurately recorded when their currency differs from the policy currency and carried through quoting, binding, policy issuance, and document generation.

## Acceptance Criteria

### AC-1 — Currency-capable fields for Excess

On the Coverages screen for the Excess product, the Occurrence Limit, Other Aggregate Limit, and Products-Completed Operations Aggregate Limit fields are text inputs that can accept a currency together with the limit amount.

### AC-2 — Currency-capable Other Limit entries

For each row in the Other Limit section, the Limit of Liability field is a text input that can accept a currency together with the limit amount.

### AC-3 — Currency is not forced to the policy currency

Users can record a valid limit using a supported currency that differs from the policy currency. The application does not silently replace the entered currency with the policy currency or discard the currency information.

### AC-4 — Entered values are preserved

Each field retains its own entered currency and limit when the user continues through the workflow and saves or retrieves the submission. Updating one limit does not change the values in other limit fields or Other Limit rows.

### AC-5 — Validation remains clear and non-destructive

The application accepts entries that follow its supported currency-and-limit input rules. If an entry is invalid, the user receives a clear validation message; the application does not silently truncate, strip, or convert the entered currency or amount.

### AC-6 — Available in both submission paths

The currency-capable fields are available for Excess submissions reached through both:

1. EzDocs Liability, using an existing submission retrieved by submission number.
2. Received Liability, using the create-submission flow reached with a contract ID.

### AC-7 — Values carry through quote, bind, and policy

After the user completes the applicable workflow, the currency and amount entered for each of the four limit types remain associated with the correct coverage or Other Limit entry in the quote, binder, and policy.

### AC-8 — Generated documents show the entered values

Generated documents display the currency and limit amount for each applicable field and Other Limit entry as entered and associated with the correct coverage. The document output does not substitute the policy currency or omit the currency component.
